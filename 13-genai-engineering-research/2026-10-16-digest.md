# GenAI engineering research digest — 2026-10-16

Published after the 2026-10-09 digest. All five selections are original research preprints. Numerical results are author-reported and should be reproduced on local workloads before influencing production decisions.

## 1. Diagnose RAG configuration faults across stage boundaries — 2026-10-13

**Source:** [Configuring RAG Systems: What Breaks, Where Originates, and How to Fix](https://arxiv.org/abs/2610.18567)

**Finding:** The authors study 654 real-world configuration issues from 10 RAG systems and report that the stage where a symptom appears often differs from the stage containing its root cause.

**Evidence limit:** Preprint based on mined issue reports; the taxonomy describes the sampled open-source systems and does not establish failure prevalence in private enterprise deployments.

**Why it matters:** A bad answer may look like a generation failure while originating in parsing, indexing, embedding, retrieval, or configuration compatibility. Tuning the final prompt first can hide rather than fix the fault.

**Try it:** Give every configuration change an owner, schema, default, version and validation rule. Add stage-level health checks for ingestion, indexing, retrieval, context assembly and generation, then inject five bad configurations and measure time-to-localize.

## 2. Test coding agents against held-out requirements — 2026-10-09

**Source:** [AgentSWE: Can Coding Agents Build the Agent You Actually Want?](https://arxiv.org/abs/2610.13361)

**Finding:** Across 25 agent-building tasks covering creation, editing and optimization, the benchmark separates illustrative cases visible during development from held-out acceptance cases. The authors report recurring overfitting, apparently complete code with hollow runtimes, and unsupported completion claims.

**Evidence limit:** Preprint benchmark with a small task set and specific agents/harnesses; the abstract does not provide a single aggregate success rate to generalize.

**Why it matters:** An agent can satisfy the examples in a ticket while missing the operational contract, exactly as an integration can pass happy-path mocks while failing real callbacks, permissions or recovery behavior.

**Try it:** For one coding-agent task, write a requirement-derived rubric before execution. Expose only two examples to the builder; keep boundary, failure, restart and authorization cases hidden for an independent acceptance gate.

## 3. Spend multi-agent compute on planning first — 2026-10-12

**Source:** [Scaling Inference-Time Compute with Teams of Coding Agents](https://arxiv.org/abs/2610.17471)

**Finding:** On ProgramBench, the authors report that teams beat a solo agent but cost 3–7 times more. Planning-only delegation matched delegation across planning, implementation and verification at about half the cost in one homogeneous setup; cheap planners helped, while cheap implementers reduced reward.

**Evidence limit:** Author-reported results on one coding benchmark and experimental harness; the optimal split may change with repository size, task type, latency target and model mix.

**Why it matters:** “Add more agents” is not an architecture. Delegation should be a budgeted decision tied to a stage where independent work adds measurable information.

**Try it:** Compare three workflows on the same repository tickets: solo, parallel planning with one implementer, and parallel implementation. Record pass rate, wall time, tokens, duplicate edits and merge conflicts; retain delegation only where it improves the quality-cost frontier.

## 4. Treat reusable subagents like governed capabilities — 2026-10-14

**Source:** [LAGO: Language Agents with Reusable Growing Options](https://arxiv.org/abs/2610.19843)

**Finding:** LAGO stores successful specialized agents as reusable “options” that a meta-agent can retrieve or create. The authors report 58.6% resolution on 500 SWE-bench Verified tasks with frozen Qwen3.5-35B-A3B, and a 50-task ablation resolved six fewer tasks without the library.

**Evidence limit:** Preprint with author-reported benchmark results; component causality is explicitly task- and model-dependent, and a reusable library introduces lifecycle and contamination risks not resolved by the headline score.

**Why it matters:** Persistent agent skills can reduce repeated decomposition work, but they become production assets that need provenance, tests, versioning, permissions and retirement rules.

**Try it:** Store one proven integration subagent as a versioned capability manifest: purpose, input/output schema, allowed tools, test suite, provenance, success metrics and expiry. Require verification before promotion and rerun its tests when models or tools change.

## 5. Use deterministic aggregation for questions over agent history — 2026-10-14

**Source:** [Beyond Retrieval: Evidence Access and Event Aggregation in Agent Memory](https://arxiv.org/abs/2610.19474)

**Finding:** TallyMem preserves source-addressable trajectories and adds an executable event ledger for aggregation. On 776 questions from 99 held-out MINTEval repositories, the authors report exact match rising from 35.2% to 49.0%; the gain on full AMA-Bench was only 1.3 points.

**Evidence limit:** Preprint with commit-specific adaptation and model-generated event specifications; benefits varied substantially by task, and event-specification errors remained the largest residual system-error category.

**Why it matters:** Vector retrieval can find a transaction or tool event, but it is a poor substitute for computing counts, totals, latest states or policy transitions over a trace.

**Try it:** Keep immutable source events plus a typed derived ledger. Route “what happened?” questions to evidence retrieval and “how many/when/what is the current state?” questions to deterministic queries, returning provenance for every aggregate.

## Suggested focus this week

Build a **requirement-derived acceptance gate** for one coding-agent workflow. Keep failure, restart and authorization cases hidden from the builder, then combine the results with stage-level telemetry to distinguish implementation errors from configuration errors.
