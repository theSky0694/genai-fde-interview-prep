# GenAI engineering research digest — 2026-10-02

Published since the 2026-09-25 digest. The results below are from original research papers; all five are arXiv preprints, and reported performance is the authors' own evaluation.

## 1. Page-aware RAG for PDFs — 2026-09-28

**Source:** [Page-Aware Retrieval-Augmented Generation for EvalLLM 2026](https://arxiv.org/abs/2609.34776)

**Finding:** In a 595-question French-PDF evaluation, the authors' full pipeline reached MRR@10 0.4450 and Recall@10 0.4013 versus 0.3430 and 0.2994 for BM25. Dense retrieval alone and simple lexical–dense fusion underperformed BM25; reranking and query decomposition helped, but decomposition increased latency and output artifacts.

**Why it matters:** Enterprise document RAG often needs the correct source page as much as a plausible answer. Adding embeddings does not automatically improve retrieval.

**Try it:** Build 30–50 bank-policy questions with gold document and page IDs. Compare BM25, dense, fusion, and reranking using page Recall@10, answer faithfulness, latency, and cost before adding query decomposition.

## 2. Diagnose agent failures by stage — 2026-09-28

**Source:** [AgentHop: A Diagnostic Benchmark for Agentic Multi-Hop Scientific Question Answering](https://arxiv.org/abs/2609.34428)

**Finding:** The authors evaluated 19 models on 1,011 questions in a seven-tool sandbox and separated failures across retrieval, synthesis, tool calling, and resource use. Models with similar overall accuracy showed different stage-level weaknesses.

**Why it matters:** A single task success rate can hide whether an integration failed because evidence was missing, a tool was called incorrectly, or the answer misused good evidence. The benchmark is scientific QA, so its model rankings should not be assumed to transfer to banking.

**Try it:** Tag each failed bank-assistant trace with those four stages. Measure stage-level error rates and fix the largest category first.

## 3. Preferences get lost across tool plans — 2026-09-28

**Source:** [PDEU-Bench: Benchmarking the Personalized Planning Lifecycle of Tool-Calling LLM Agents](https://arxiv.org/abs/2609.34930)

**Finding:** Across 214 tasks, 94 tools, and 15 models, the authors found that preference adherence in individual calls did not reliably carry through plan creation, execution, and updates. Memory methods helped some stages without consistently improving the full workflow.

**Why it matters:** A LangGraph workflow can execute every API call successfully yet violate a user or bank constraint after replanning.

**Try it:** Put durable constraints in typed state. At each plan update and before a consequential tool call, run deterministic checks for authorization, data residency, and user preferences. Test interruption-and-resume paths.

## 4. Let the agent maintain explicit working context — 2026-09-29

**Source:** [Context Language Models](https://arxiv.org/abs/2609.37725)

**Finding:** The authors let agents edit a context file. They report higher accuracy with lower compute than competing context-management methods on several long-horizon benchmarks, including an 11.4% accuracy gain with 21.5% fewer FLOPs on BrowseComp-Plus. These are author-reported preprint results, not a guarantee for enterprise workloads.

**Why it matters:** Long LangGraph and coding-agent runs accumulate tool outputs, stale plans, and duplicated evidence. Explicit context gives you an inspectable boundary for what survives.

**Try it:** Prototype a short, versioned working-memory record containing goal, verified facts with source IDs, open questions, and next actions. Compare it with conversation truncation on long tasks; audit for lost constraints and stale facts.

## 5. Coding agents need a documentation gate — 2026-09-30

**Source:** [DoGBench: Can Agents Meet Expert Standards for User-Facing Documentation?](https://arxiv.org/abs/2609.39909)

**Finding:** On a 117-item held-out split, the top of seven agents scored 47.3/100 under the authors' composite documentation-and-abstention rubric. In a separate 1,267-patch audit, common errors included task-completion gaps, technical inaccuracies, and incomplete coverage.

**Why it matters:** An agent may ship a working API change while leaving setup guides, examples, and reference pages inconsistent.

**Try it:** Add a PR checklist or agent step that checks whether API, schema, or workflow changes require documentation. Review examples against executable code, search for all affected pages, and allow an explicit “no documentation change” decision with a reason.
